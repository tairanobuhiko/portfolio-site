## 1. なぜ作り直すのか

このサイトは 2024 年の転職活動のために作った。今も公開されているが、中身は 2025 年 4 月で止まっている。

- 「現在の仕事」として書いてある会社は、すでに前職になっている。
- 実績 2 件はどちらもサービス停止中で、停止中アプリのテスト用 ID とパスワードが載ったままになっている。
- 最近の活動（Zenn の記事、新しい制作物）が載っていない。
- 見た目が当時のスクールのひな形のままで、印象に残らない。

| 副 | 採用担当、仕事を頼みたい人 | 経歴と実績を見て、連絡してもらう |

## 3. 目標、やらないこと、失敗とみなすこと

### 目標

- 中身を 2026 年 11 月時点の事実に合わせる。
- 見た目を大きく変え、動きのある目を惹くページにする（6 章の B 案）。
- 転職活動のためだけの情報を外す。
- 表示を軽くする（画像の合計を今の約 27MB から 2MB 以下にする）。
- スマホ幅でも崩れずに読める。

### やらないこと

- フレームワークやビルドの仕組みの導入。
- Zenn の記事一覧の自動取得（8 章に理由）。
- 実績ページへの OGP 設定の追加、お問い合わせフォーム、ダークモード、多言語対応。
- 公開のしくみ（GitHub Pages の設定）の変更。
- main ブランチへの取り込み。取り込むと即公開されるので、ユーザーの指示があってから別の手順で行う。

### 失敗とみなすこと

- 独自ドメインが外れる（`CNAME` ファイルを消す、書き換える）。
- 転職活動用の情報（生年月日、テスト用アカウント、テスト用カード番号）が残る。
- 動きが多すぎて文章が読みにくい。OS で「動きを減らす」設定にしている人にも演出の動きを見せてしまう（止める範囲は 6.3）。
- 確定した文言（5 章）を勝手に言い換える。
- 今より表示が重くなる。

## 4. 守る条件

- 公開は GitHub Pages。main ブランチの直下がそのまま公開される（`source: main, path: /`、ビルド方式は legacy）。
- `CNAME`（中身は `tairanobuhiko.com`）は触らない。
- Google アナリティクスのタグ（`G-LES68TYGT9`）は全ページに今のまま残す。
- 実績の詳細ページの URL `works/02.html` は変えない。過去の記事などから張られたリンクを切らないため。
- 文言は 5 章のとおりにする。画面に出ない文言と短い表示は 5.12 にまとめた。5 章にない文を足す必要が出たら、ユーザーに確認する。
- 絵文字は使わない。

### 6.3 動きについての決まり

- OS で「動きを減らす」（`prefers-reduced-motion: reduce`）にしている人には、演出の動きを止め、中身を最初から表示する。止める・残すの区別は次のとおり。
  - 止める: CSS のアニメーションと変化の動きすべて（せり上がり、揺れ、回転、流れる帯、ふわっと現れる動き、線が伸びる動き、マウスを乗せたときの動き）。
  - 止める: メニューを押したときのなめらかなスクロール。すぐにその欄へ移動させる。
  - 出さない: WORKS でマウスに付いてくる画像。画像は詳細ページと公開中のサイトで見られる。
  - 残す: 画面上端の読み進みの線。見る人自身のスクロールに合わせて伸びるだけで、スクロールバーと同じ働きのため。
  - JavaScript の側でもこの設定を見て、上の区別どおりに動かす。
- JavaScript が動かない環境でも、文章と画像がすべて見える。「スクロールで現れる」ための非表示は、JavaScript が動いたときだけ有効にする。
- WORKS の「マウスに付いてくる画像」は、マウスがある端末（`hover: hover`）でだけ出す。
- キーボードで移動したときに、今どこにいるかが分かる枠を出す。

### 6.4 スマホ幅（860px 以下）

- 各欄は 1 列に並べる。
- メニューはボタンで開閉する形にする。開くと 5 項目が縦に並ぶ。項目を押すと閉じる。
- 人物画像は名前の下に置く。
- 経歴の線は縦向きにする。
- 横スクロールが出ないこと。

## 7. 作り方

### 7.1 比べた案

| 案 | 内容 | 判断 |
| --- | --- | --- |
| 1. 素の HTML / CSS / JavaScript で書き直す | ビルドなし。jQuery と SCSS をやめる | 採用（エージェントの判断。ユーザーは作り方を任せた） |

### 7.4 公開から外すフォルダ

GitHub Pages は main の中身をそのまま公開するので、`docs/` と `tests/` も URL で見えてしまう。`_config.yml` に `exclude` を書いて、この 2 つと `README.md` を公開から外す。リポジトリ自体は公開なので中身は秘密ではないが、サイトの URL からは見えないようにする。

この指定は手元では確かめられない（GitHub 側の変換の仕組みが手元にないため）。公開したあとに `https://tairanobuhiko.com/docs/` が「ページがありません」になることを見て確かめる。指定がうまく働かなくても、サイトの表示には影響しない。

## 8. エージェントが決めたこと（ユーザーに直接は聞いていない点）

| 決めたこと | 理由 |
| --- | --- |
| Zenn の記事一覧は HTML に手で書く | Zenn の記事取得の窓口はブラウザからの直接の呼び出しを許していない。自動化には別の仕組みが要り、やりすぎになる |
| 詳細ページの URL は `works/02.html` のまま | 過去に張られたリンクを切らないため |
| 古い人物写真は消す | 使わなくなる。本人の顔写真を使わないまま公開し続ける理由がない |
| favicon を足す | 今はなく、ブラウザのタブが空白の印になる。1 ファイルで済む |
| `_config.yml` で `docs/` と `tests/` を公開から外す | 7.4 のとおり |
| 詳細ページの「OTHERS その他実績」欄をなくし、WORKS へ戻るリンクにする | 実績の一覧はトップページに 1 か所あれば足りる |
| コミットはユーザーの指示があってから行う | 作業ブランチでも、勝手にコミットしない取り決めのため |
| 画面に出ない文言と短い表示（5.12）を決めた | 代替テキストや読み上げ用の名前は必ず要る。どれも確認済みの名前や見たままの説明で、中身の判断を伴わない |
| 「動きを減らす」設定で止める範囲（6.3）を決めた | 演出は止め、見る人の操作をそのまま映す読み進みの線だけ残す |
